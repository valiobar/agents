# Knowledge Base Service Architecture

## Responsibility

The Knowledge Base Service owns unstructured knowledge and vector retrieval. It handles user document upload, document lifecycle metadata, text extraction, chunking, embeddings, ChromaDB vector storage, shared tax knowledge, and `POST /retrieve` for RAG consumers.

## Implemented Layers

```text
routes/ -> services/ -> repositories/ -> models/
                     \-> adapters/
                     \-> embeddings/
```

| Layer | Files | Responsibility |
|-------|-------|----------------|
| `routes/` | `health.py`, `documents.py`, `retrieval.py` | FastAPI endpoints, dependency injection, response models |
| `services/` | `document_service.py`, `ingestion_service.py`, `retrieval_service.py`, `tax_preload_service.py` | Lifecycle rules, ingestion orchestration, query merge/rank behavior, startup tax preload |
| `repositories/` | `document_repo.py` | MongoDB `documents` metadata access |
| `adapters/` | `vector_store.py`, `chroma.py` | Vector store contract and ChromaDB implementation |
| `embeddings/` | `provider.py` | Batched OpenAI embedding calls |
| `models/` | `document.py`, `retrieval.py` | Pydantic request, response, persistence, and chunk metadata schemas |

Routes never access MongoDB or ChromaDB directly. Metadata persistence goes through `DocumentRepository`; vector operations go through `VectorStore`/`ChromaAdapter`; embedding calls go through `EmbeddingProvider`.

## Main Patterns

- **Layered architecture:** routes are thin and delegate business logic to services.
- **Repository pattern:** MongoDB metadata persistence is isolated in `DocumentRepository`.
- **Adapter pattern:** ChromaDB details are hidden behind the `VectorStore` contract.
- **Content hash deduplication:** `compute_sha256` prevents re-embedding unchanged ready documents for the same user.
- **Async boundary management:** FastAPI routes and I/O orchestration are async; blocking PDF, ChromaDB, and filesystem calls are wrapped with `asyncio.to_thread`.

## Collections

| Store | Collection | Purpose |
|-------|------------|---------|
| MongoDB | `documents` | User document metadata, status, content hash, chunk count |
| ChromaDB | `global_tax` | Shared tax regulation chunks loaded from `TAX_DOCS_PATH` |
| ChromaDB | `user_{user_id}` | Chunks for a single user's uploaded documents |

MongoDB stores no raw file bytes. ChromaDB stores chunk text, embeddings, and metadata needed to attribute retrieval results.

## Startup

`app/main.py` uses FastAPI lifespan to connect to MongoDB, ping it, create `documents` indexes, optionally preload tax documents, then close the Motor client on shutdown. `PRELOAD_TAX_DOCS=false` by default so local startup does not require an OpenAI key unless embeddings are generated by uploads or retrieval.

## Endpoint Contracts

| Route | Response Model | Notes |
|-------|----------------|-------|
| `GET /health` | `dict[str, str]` | Public health check |
| `POST /documents` | `DocumentResponse` | Requires `x-user-id`, multipart `file`, returns `201` |
| `GET /documents` | `list[DocumentResponse]` | Requires `x-user-id`, supports `limit` and `offset` |
| `PUT /documents/{document_id}` | `DocumentResponse` | Requires `x-user-id`, multipart `file` |
| `DELETE /documents/{document_id}` | `204 No Content` | Requires `x-user-id` |
| `POST /retrieve` | `RetrievalResponse` | Uses request `user_id` or `x-user-id`; can search global and user collections |

## Restrictions

- Every endpoint must remain `async def`.
- User-scoped document operations must require `x-user-id`.
- Public response models must not expose ChromaDB client internals.
- MongoDB indexes must support document list, deduplication, and status filters.
- Retrieval results should include only chunk text, score, collection name, and chunk metadata needed by downstream agents.
